# 阶段收口计划

> 目标：把 P3.8 后端收口后的开放项、前端对接、后端缺口和 P4 能力按依赖顺序逐项完成。
> 状态记录以本文档为唯一入口；每个阶段完成后单独提交并推送到 `gitee` 与 `github`。

## 状态图例

| 状态 | 含义 |
|---|---|
| ⬜ 未开始 | 尚未动工 |
| 🔄 进行中 | 已开工，未全部完成 |
| ⏸ 待用户验证 | 代码/文档已完成，等待用户按清单验证 |
| ✅ 已完成 | 代码/文档/验证均完成 |

## 阶段总览

| 阶段 | 目标 | 状态 |
|---|---|---|
| S0 基线收口 | 收口当前未提交批次，提交推送，合并 `main`，创建后续工作分支 | ✅ 已完成 |
| S1 AUTO_PASS 基线实测 | 构造 20~30 个样本，量化自动通过率与审核原因分布 | ⬜ 未开始 |
| S2 前端对接闭环 | 完成 P3.8 后端能力的前端接入与体验闭环 | ⬜ 未开始 |

## S0 · 基线收口 ✅

**范围**
- 复核当前 26 个未提交文件的收口内容。
- 将 P3.8 后端收口批次提交并推送到双仓库。
- 合并 `refactor/agent-autonomy-hardening` 到 `main`，并推送双仓库。
- 从 `main` 创建统一后续工作分支，避免跨阶段分支漂移。

**验收标准**
- 工作区无未提交改动。
- `main` 包含 P3.8 后端全部提交。
- 后续阶段在统一分支上推进。

**交付物**
- 本计划文档。
- 当前收口批次提交。
- `main` 合并提交。
- 后续工作分支。

## S1 · AUTO_PASS 基线实测 ⬜

**范围**
- 构造 20~30 个样本单据。
- 覆盖正常、超标、重复票、票据不一致、低置信度五类场景。
- 统计自动通过率、`reviewReason` 分布、失败原因、Token 与 OCR 成本。
- 根据结果决定是否调整 `confidence < 0.7` 阈值。

**验收标准**
- 样本全部进入终态。
- 报告可复现，脚本可重复执行。
- 无未解释异常或静默失败。

**交付物**
- 基线测试脚本。
- 基线结果记录。
- 阈值决策结论。

## S2 · 前端对接闭环 ⬜

**范围**
- S2.1 审核体验：进度轮询、进度回退提示、待修正项清单、编辑页标红预填、上传前置校验。
- S2.2 通知中心：站内信铃铛、列表、已读处理，Webhook 配置与投递台账。
- S2.3 智能分析与幂等：GENERIC 智能分析页、提交幂等键。

**验收标准**
- `npm run build` 通过。
- 核心页面手工链路可走通。
- 后端契约与前端展示一致，进度回退有机制解释。

**交付物**
- 前端页面与组件改造。
- 幂等后端小改与前端接入。
- 前端验证清单。

## S3 · 后端产品缺口 ⬜

**范围**
- S3.1 文件删除/回收接口：默认逻辑删除，不做物理删除，避免破坏审计与跨服务引用。
- S3.2 废单查看当时票据：作废时持久附件引用快照，详情页按快照重建。

**验收标准**
- 新增迁移脚本、API 文档、单测与端到端脚本。
- 文件删除不破坏历史审计与跨服务引用。
- 废单详情能还原作废时的票据视图。

**交付物**
- 数据库迁移脚本。
- 后端接口与 Service。
- API 文档与测试脚本。

## S4 · P4 可观测与评估 ⬜

**范围**
- S4.1 指标大盘：基于 `model_call_log` 与任务/步骤耗时，落地成功率、耗时、成本、纠错次数等核心图表。
- S4.2 幻觉拦截：基于 S1 基线数据定义规则，命中强制人工复核。
- S4.3 轻量调度：先落 `task-job-service` 轻量版，不引入 XXL-Job。
- S4.4 RAG / Milvus：最后实施，需先定版本、Embedding 提供方、切片策略与租户隔离模型。

**验收标准**
- 指标口径有文档，图表可用。
- 幻觉拦截规则可配置、可解释、可回放。
- 调度任务可运行、可观测、可回滚。
- RAG 不破坏现有租户与权限边界。

**交付物**
- 监控大盘与指标口径文档。
- 幻觉拦截规则与测试。
- 轻量调度服务。
- RAG 知识库最小可用版本。

## 执行纪律

- 每个阶段一个提交，提交后推送 `gitee` 与 `github`。
- 每阶段完成后更新本文档状态，再进入下一阶段。
- 涉及运行时验证的项目，代码完成后标记为 `⏸ 待用户验证`，由用户执行验证清单。
- 编译、启动、重启、执行测试由用户完成；本文档不虚报验证状态。
