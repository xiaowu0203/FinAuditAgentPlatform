## 一、项目核心定位

项目必须落地**真实商业业务痛点**，以业务价值为第一导向，完整体现大型分布式后端工程落地能力与标准化 Agent 智能体工程化落地能力；拒绝玩具式问答 Demo，禁止单纯 “用户提问 - 大模型单次回复” 的简易聊天机器人。

## 二、七大落地验收标准

### 标准 1：落地真实业务闭环，具备可量化业务指标

1. 有明确目标用户群体、清晰业务痛点，完整端到端业务流程，完整输入输出闭环；
2. 产出效果可量化评估，拥有客观指标，不靠主观感受判断效果；
3. 区分通用对话机器人与 Agent 核心差异：项目核心是**自主任务拆解、分步执行、工具联动、自主纠错**，而非单次问答；
4. 可选业务方向参考（可自定义，不局限于此）：企业智能客服、企业销售智能经营助手、企业多租户知识库 RAG 智能顾问、企业项目规划智能协同 Agent、财务费用智能审核助手。

### 标准 2：完整分布式后端工程体系（分层架构 + 多租户隔离 + 生产级基础设施）

1. 四层标准分层架构：API 网关层、业务逻辑层、数据持久层、基础设施公共层；
2. 基础工程能力强制要求：
   - 统一全局异常处理器、全局统一接口返回封装类、全局参数校验（JSR303）；
   - RBAC 细粒度权限管理、多租户数据隔离（租户数据物理 / 逻辑隔离，禁止跨租户数据泄露）；
   - 完整操作日志、业务日志、错误日志分层存储，支持按用户 / 租户 / 任务检索溯源；
   - 支持多用户高并发访问，具备并发冲突解决方案（分布式锁）；
3. 配套分布式基础设施能力：
   - 统一网关、分布式限流、接口熔断降级；
   - 文件存储、定时任务、统一配置中心、消息队列异步解耦；
4. 代码复用规范：通用能力抽取自定义 Spring Starter，避免重复配置（MybatisPlus、Redis、模型客户端、链路追踪等）。

### 标准 3：标准 Agent 核心智能能力，按需多智能体协同（拒绝过度炫技）

1. 基础自主规划能力：Agent 可自动识别复杂任务，拆解为有序子任务，自主规划执行顺序；
2. 工具调用容错机制：工具调用超时、参数错误、第三方接口异常时，支持自动重试、参数修正、熔断兜底；
3. 任务结果自校验：每一步工具执行完成后，Agent 自主校验结果合法性，异常结果自动重新执行；
4. Multi-Agent 协同约束：
   - 简单单步骤任务：仅使用单 Agent + 工具集，不强制拆分多智能体；
   - 跨领域、长周期、多专业复杂任务：按业务职责拆分独立 Agent（规划 Agent、检索 Agent、计算 Agent、审核 Agent 等）；
   - Agent 之间通过消息队列异步通信，不使用同步调用耦合；
5. 任务断点续跑：长周期任务执行中断后，可基于持久化任务状态恢复执行，不丢失进度；
6. 工具统一治理：全量工具注册至配置中心，支持动态上下线、入参 Schema 强校验、高频工具结果缓存。

### 标准 4：分层上下文工程治理，解决长文本 Token 溢出问题

1. 四类上下文分层独立存储，完全隔离：
   - 临时会话上下文（Redis 短期缓存，自动过期）；
   - 用户长期档案（MySQL 持久化存储，用户基础信息、历史偏好）；
   - 任务运行上下文（全流程子任务、工具返回数据、中间结果）；
   - 企业私有知识库（向量数据库持久化）；
2. 上下文自动治理能力：长会话自动摘要压缩、过滤无效历史，控制 Token 消耗；
3. 强隔离机制：不同租户、不同用户、不同任务上下文完全隔离，杜绝会话串话；
4. 支持人工手动清空 / 重置指定上下文。

### 标准 5：全链路可观测体系 + 自动化量化评估平台

1. 全链路追踪：完整记录一条请求全生命周期链路，包含：网关请求、Agent 调度、工具调用、大模型 API 请求、数据库操作；
2. 多维度监控指标：
   - 性能指标：接口 QPS、任务平均耗时、最大耗时、并发峰值；
   - 成本指标：各模型 Token 消耗、调用次数、预估费用；
   - 成功率指标：Agent 任务完成率、工具调用成功率、模型请求失败率；
3. 量化评估体系（自动化运行，输出报表）：
   - 任务结果准确率、大模型幻觉率、工具纠错次数；
   - 失败任务分类统计（参数错误、第三方超时、模型输出异常、权限不足）；
4. 可视化监控大盘：前端页面展示指标趋势、失败任务明细、成本统计报表。

### 标准 6：人机协同闭环，高风险节点强制人工介入

1. 配置化审批规则：可视化配置风险操作，触发后自动暂停 Agent 任务，生成人工审核工单；

   高风险场景包含：资金计算提交、对外邮件 / 消息发送、批量客户数据导出、合同生成、隐私数据查询；

2. 双向人机交互通道：

   - Agent 主动推送待审核任务，等待人工确认 / 修改；
   - 人工可随时打断运行中 Agent、修改中间结果、新增补充指令、终止任务；

3. 全审批留痕：所有人工操作、修改记录、审核意见持久化存储，支持审计溯源。

### 标准 7：大模型与工具安全风控

1. 输入 Prompt 安全拦截：恶意指令注入、违禁内容、越权指令过滤；
2. 输出内容自动脱敏：手机号、身份证、企业合同金额、客户隐私自动屏蔽；
3. 工具调用安全校验：入参防 SQL 注入、越权查询拦截，禁止跨租户数据查询；
4. 模型输出幻觉拦截：评估体系内置幻觉检测规则，异常结果标记并推送人工复核。

## 三、技术栈硬性规范

### 整体架构约束

1. 整体为**Spring Cloud 分布式微服务架构**，前后端完全分离；
2. 全部组件支持 Docker 容器化部署，提供一键启动 Docker Compose 脚本；
3. 开发环境隔离：Nacos 多命名空间区分 dev/test 环境，配置文件环境隔离。

### 后端技术栈（Java 体系）

1. 基础运行环境
   - JDK 21
   - Spring Boot 3.5.0
   - Spring Cloud 2025.0.0（配套 SpringBoot 版本，版本统一管理）
2. 数据持久层
   - MySQL 5.7
   - Mybatis Plus 3.5.10
   - Redis（分布式缓存、分布式锁、临时上下文存储、限流）
   - Milvus 向量数据库（企业知识库 RAG 检索基础设施）
3. 中间件（本地已有环境，直接复用）
   - Nacos 3.2.2：统一配置中心、服务注册发现
   - RabbitMQ 3-management：Agent 异步通信、任务分发、解耦
4. 网关与监控链路
   - Spring Cloud Gateway：统一网关，鉴权、限流、路由、跨域
   - SkyWalking：分布式链路追踪
   - Prometheus + Grafana：指标监控大盘（可选）
   - Logback + ELK 简易日志收集方案（可选）
5. 配套基础设施组件
   - MinIO：本地对象存储，存储文档、报表、Agent 生成文件
   - XXL-Job：分布式定时任务（定时刷新向量库、清理过期上下文、生成评估报表）
6. 模型统一封装
   - 自定义 model-spring-starter：统一对接 Qwen/DeepSeek/Claude 等多模型（默认使用DeepSeek），统一管理密钥、统计 Token 消耗、故障自动切换备用模型
7. 测试组件
   - JUnit5 + Mockito：单元测试
   - TestContainers：数据库、消息队列集成测试（可忽略）

### 前端技术栈（统一方案，可审核调整）

1. 基础框架：Vue3 + Vite
2. UI 组件库：Element Plus
3. 状态管理：Pinia
4. 网络请求：Axios（全局统一拦截、异常封装）
5. 可视化图表：ECharts（监控大盘、评估报表）
6. 工程规范：路由权限控制、页面操作埋点、全局异常弹窗
7. 页面规划：
   - 租户 / 用户、RBAC 权限管理页面
   - Agent 任务工作台：新建任务、查看进度、人工审批工单
   - 知识库管理：文档上传、向量检索、文档权限配置
   - 系统配置：Agent 角色配置、工具配置、审批规则可视化配置
   - 监控评估大盘：性能、成本、成功率可视化报表
